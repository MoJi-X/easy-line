# Flex Message 构建模块开发规格

## 目标与边界
- 目标：将告警分析结果转换为 LINE Flex Message 格式，支持代码构建与 LLM 构建两种方式，并具备降级机制。
- 范围内：`src/services/flex-message-code-builder.ts`、`src/services/flex-message-llm-builder.ts`、配置开关、降级策略、Flex Message 结构定义。
- 范围外：告警分析 SSE 处理、Agent 状态机、工单创建。

## 任务拆分

### FLEX-001 配置开关与类型定义
- goal：定义 Flex Message 构建方式的配置开关和相关类型。
- inputs：08 文档 3.1、3.2、3.3；需求文档 5.1。
- outputs：`FLEX_MESSAGE_BUILDER` 环境变量解析、`FlexMessageBuilderType` 类型、`FlexMessage` 结构定义。
- dependencies：`specs/10-line-message.spec.md` 的 LINE-001。
- implementation notes：配置值支持 `code` 和 `llm`，默认为 `code`；类型定义需符合 LINE Flex Message 规范；配置解析失败时使用默认值并记录警告日志。
- acceptance criteria：配置可正确读取；非法值时回退到 `code` 并有明确日志；类型定义完整覆盖 Flex Message 结构。

### FLEX-002 代码构建器实现
- goal：通过预定义代码逻辑构建告警分析 Flex Message。
- inputs：08 文档 2.1、6.1、6.2；告警分析结果结构。
- outputs：`buildAlarmAnalysisFlexMessage` 函数、样式映射函数、Flex Message 模板。
- dependencies：FLEX-001。
- implementation notes：模板结构包含 header、body、footer；样式映射需支持派单/观察/关闭/忽略四种动作的颜色和文本；告警对象信息需包含设备名称、告警类型、告警等级、置信度；研判理由需支持长文本截断；altText 需包含设备名称和动作文本。
- acceptance criteria：输入告警分析结果后输出符合 LINE Flex Message 规范的 JSON；不同动作类型显示对应颜色和文本；关键字段完整无缺失。

### FLEX-003 LLM 构建器实现
- goal：通过大语言模型智能解析并生成 Flex Message。
- inputs：08 文档 2.2、5.1、5.2；告警分析结果、告警原始数据。
- outputs：`FlexMessageLLMBuilder` 类、提示词模板、JSON 清理与解析逻辑。
- dependencies：FLEX-001、LangChain 模型接入。
- implementation notes：提示词需明确要求只输出 JSON、不使用 Markdown 代码块、符合 LINE Flex Message 结构；输出处理需清理可能的 Markdown 代码块标记；解析失败时返回 null 触发降级；LLM 调用需设置超时。
- acceptance criteria：LLM 输出可被正确解析为 Flex Message JSON；Markdown 代码块标记被正确清理；解析失败时返回 null 而非抛出异常。

### FLEX-004 降级策略与统一入口
- goal：实现 LLM 构建失败时的自动降级，并提供统一构建入口。
- inputs：08 文档 4.2、4.3；FLEX-002、FLEX-003。
- outputs：降级判断逻辑、统一构建入口函数、降级日志。
- dependencies：FLEX-002、FLEX-003。
- implementation notes：降级触发条件包括 LLM API 调用超时、返回内容无法解析为 JSON、JSON 不符合 Flex Message 结构、LLM 服务不可用；降级时需记录警告日志；统一入口根据配置选择构建方式并处理降级。
- acceptance criteria：LLM 模式下构建失败时自动降级到代码构建；降级日志清晰记录原因；用户始终能收到有效的 Flex Message。

### FLEX-005 告警分析 Flex Message 集成
- goal：将 Flex Message 构建器集成到告警分析 Tool 中。
- inputs：08 文档 4.2；`specs/25-alarm-integration-tools.spec.md` 的 ALARM-003。
- outputs：`analyze_alarm` Tool 返回 Flex Message、Tool 层构建逻辑。
- dependencies：FLEX-004、`specs/25-alarm-integration-tools.spec.md` 的 ALARM-003。
- implementation notes：Tool 层根据配置选择构建方式；构建结果附加到 Tool 返回值中；构建失败不影响分析结果本身；需在 Tool 日志中记录构建方式和耗时。
- acceptance criteria：`analyze_alarm` Tool 返回值包含 `flex_message` 字段；配置切换后构建方式随之改变；构建失败时分析结果仍可用。

## 验收与测试
- 单元验证：配置解析、代码构建器模板渲染、LLM 构建器 JSON 清理、降级判断逻辑。
- 集成验证：`analyze_alarm` Tool 返回有效 Flex Message；LLM 模式降级到代码模式。
- 演示验收：用户收到告警分析结果后，LINE 端显示格式正确的 Flex Message 卡片。

## 风险与回退
- 风险：LLM 输出格式不稳定可能导致频繁降级。
- 风险：Flex Message 结构变化需要同步更新代码构建器和 LLM 提示词。
- 回退：若 LLM 构建不稳定，可临时切换到纯代码模式；若代码构建有问题，可回退到纯文本消息。

## 本轮实现记录
- scope: 本轮实现 `FLEX-001`、`FLEX-002`、`FLEX-003`、`FLEX-004`、`FLEX-005`，完成 Flex Message 构建模块的完整功能。
- decision: 配置开关默认使用 `code` 方式，保证生产环境稳定性；LLM 方式用于 Demo 和快速迭代场景。
- decision: 降级策略在 Tool 层实现，不暴露给上层 Agent。
- decision: Flex Message 结构遵循 LINE 官方规范，使用 bubble 容器和 box 布局。
- deferred: 暂不实现 hybrid 混合构建方式；暂不支持自定义 Flex Message 模板。

## 当前实现基线
- Flex Message 构建模块已独立为 `specs/26.5-flex-message-builder.spec.md`。
- 支持代码构建和 LLM 构建两种方式，通过 `FLEX_MESSAGE_BUILDER` 环境变量切换。
- LLM 构建失败时自动降级到代码构建，确保用户始终能收到有效消息。
- 下一步需要在 `specs/25-alarm-integration-tools.spec.md` 和 `specs/26-alarm-agent-workflow.spec.md` 中添加对本模块的依赖。
