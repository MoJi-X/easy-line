---

## 1. 目标概述

本轮开发计划围绕“统一 Agent + 动态天气任务 + Tavily 搜索”展开，原则上遵循：

- 先文档评审，再拆 spec
- 先统一消息入口，再补工具和任务能力
- 先完成最小可运行切片，再做治理与收尾

---

## 2. 实施顺序

### 阶段 0：文档评审

**目标**

- 完成需求、架构、接口、存储、项目计划的同步更新
- 补充独立评审文档，锁定产品取舍

**交付物**

- `docs/需求规格说明书.md`
- `docs/动态任务与Agent重构需求变更说明.md`
- 支撑文档同步更新

### 阶段 1：LINE 链路与统一 Agent 骨架

**目标**

- 保持 `POST /webhook` 与签名校验稳定
- 把消息处理主链路切到统一 Agent 入口
- 让 `/chat` 与 LINE 消息走同一流程

**验证点**

- Webhook 可接收文本消息
- `/chat` 能复用同一 Agent 流程
- 普通聊天在不调用工具时可正常回复

### 阶段 2：工具标准化与 Tavily 接入

**目标**

- 建立 Tool Registry
- 先接入 Tavily 搜索工具
- 明确 Agent 自动决策与降级行为

**验证点**

- 实时信息问题会触发 `search.tavily`
- 搜索失败时能降级回复
- 工具日志可追踪

### 阶段 3：动态任务 CRUD 与 JSON 持久化

**目标**

- 实现自然语言与 `/task` 双轨任务管理
- 由 Task Repository 管理内存索引与 JSON 回写
- 只支持“当前用户自己的每日天气任务”

**验证点**

- 自然语言创建任务成功
- `/task create|list|update|delete` 语义稳定
- `src/config/tasks.json` 可回写并在重启后重载

### 阶段 4：天气调度执行与刷新

**目标**

- CRUD 后刷新调度器注册
- 定时执行天气查询和主动推送
- 提供手动执行与最近执行记录

**验证点**

- 每日任务能按计划触发
- 手动执行可用
- 单任务失败不影响其他任务

### 阶段 5：治理与验收

**目标**

- 校对 `/chat` 与 LINE 链路一致性
- 补齐日志、健康检查、异常路径验证
- 评审通过后再拆新的 `specs/*.spec.md`

**验证点**

- `/health` 状态可读
- 异常路径返回稳定结构
- 文档与后续 spec 边界一致

## 3. 里程碑与验收

| 里程碑 | 核心结果 | 通过标准 |
|--------|---------|---------|
| M1 | 文档评审完成 | 需求和支撑文档无明显冲突 |
| M2 | 统一 Agent 入口跑通 | `/webhook` 与 `/chat` 共用一套消息链路 |
| M3 | 工具能力可演示 | Tavily 搜索可被 Agent 调用 |
| M4 | 动态任务闭环跑通 | 任务 CRUD + JSON 持久化可用 |
| M5 | 定时天气推送可演示 | 调度、执行、推送、日志完整 |

---

## 4. 当前切片优先级

| 优先级 | 能力 | 说明 |
|--------|------|------|
| P0 | LINE 主链路稳定 | Webhook、签名校验、Reply |
| P0 | 统一 Agent 入口 | 所有用户消息都先走 Agent |
| P1 | Tavily 搜索工具 | 展示自动决策能力 |
| P1 | 动态任务 CRUD | 自然语言与 `/task` 双轨 |
| P1 | JSON 持久化 | 重启后可重载 |
| P2 | 调度刷新与执行日志 | 提升演示完整度 |

---

## 5. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| Agent 改造导致消息主链路波动 | 影响 LINE 演示 | 保留最小降级回复与快速确认 |
| JSON 持久化规则不清晰 | 影响任务一致性 | 先在文档中冻结回写流程 |
| Tavily 或天气 API 不稳定 | 影响工具与推送演示 | 增加超时、错误降级和可读日志 |
| 范围膨胀到复杂调度平台 | 拖慢 Demo 交付 | 固定任务类型与调度语义 |

---

## 6. 文档与 Spec 协作方式

- 当前阶段先完成文档评审，不直接修改 `specs/*.spec.md`
- 评审通过后，再按以下主线拆 spec：
  1. Agent 入口与工具框架
  2. 动态任务 CRUD 与 JSON 持久化
  3. 天气调度执行与任务生命周期
- 当前 spec 体系已更新为 `10-line-message`、`20-agent-orchestrator`、`30-task-crud-persistence`、`35-weather-scheduler-lifecycle`、`40-api-governance`
